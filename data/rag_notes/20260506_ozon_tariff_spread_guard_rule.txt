OZON TARIFF SPREAD GUARD RULE / 2026-05-06

Назначение:
Это внутреннее правило Seller Helper для защиты пользователя от ошибочного расчета маржи по слишком широким категориям Ozon.

Источник наблюдения:
Внутренний аудит стандартного тарифного файла Ozon:
20260426_141844_marketplace-services-rates-01-04-2026.xlsx
Слой: marketplace_service_rate.
Это не Ozon Select и не commission_only.

Ключевое наблюдение:
В стандартной тарифной базе Ozon по ряду пользовательских слов есть сильный разброс ставок между смежными категориями.

Примеры:

1. Чайники:
- электрочайники и термопоты: примерно 38% / 45%;
- чайники походные: примерно 40% / 47%;
- заварочные чайники и обычные чайники в посуде: примерно 43.5-51%;
- аксессуары и грелки на чайник также могут попадать в высокий тарифный диапазон.

2. Шампуни:
- обычные, сухие и твердые шампуни в категории ухода за волосами: примерно 5% / 12%;
- автошампуни: примерно 39% / 46%;
- шампуни для малышей: примерно 41% / 48%.

3. Бытовая химия и чистящие средства:
- общий слой бытовой химии, средства для посуды, средства для стирки и смежные товары могут иметь тарифы около 44-53%.

Правило для Seller Helper:
Если пользователь пишет широкий запрос по Ozon без уточнения подтипа товара, бот не должен сразу считать маржу по первому найденному совпадению.
Нужно запросить уточнение категории или конкретный тип товара.

Примеры широких запросов:
- Ozon чайник
- Ozon шампунь
- Ozon средство
- Ozon бытовая химия
- Ozon чистящее средство
- Ozon моющее средство

Примеры уточненных запросов:
- Ozon чайник электрический
- Ozon чайник походный
- Ozon чайник заварочный
- Ozon сухой шампунь
- Ozon твердый шампунь
- Ozon автошампунь
- Ozon детский шампунь
- Ozon средство для посуды
- Ozon средство для стирки

Публичное объяснение пользователю:
Лучше уточнить категорию до расчета, чем показать красивую, но неверную маржу.
Особенно опасны категории, где смежные товары отличаются по ставке на десятки процентных пунктов.

Статус:
Справочное RAG-правило и продуктовый guard.
Числовые расчеты по-прежнему должны брать комиссии из clean_commissions / marketplace_service_rate.
RAG не является источником числового тарифа, а объясняет причину защитной логики.
